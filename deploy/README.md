# Подизање

Један артефакт, произвољан број инстанци. Префикс не улази у грађевину — стиже кроз
`ENVIRONMENT` при подизању контејнера.

```
docker compose -f deploy/docker-compose.yml up --build
```

Резултат су две инстанце из **истог образа**:

| инстанца | адреса                        | префикс     | писмо    |
| -------- | ----------------------------- | ----------- | -------- |
| magacin1 | http://localhost:8081/Magacin1/ | `/Magacin1` | ћирилица |
| magacin2 | http://localhost:8082/Magacin2/ | `/Magacin2` | латиница |

## Променљиве

| променљива        | обавезна | значење                                        |
| ----------------- | -------- | ---------------------------------------------- |
| `ENVIRONMENT`     | да       | префикс инстанце; `/` за корен                 |
| `JAVA_UPSTREAM`   | не       | Java backend, подразумевано `java-backend:8080` |
| `DOTNET_UPSTREAM` | не       | .NET backend, подразумевано `dotnet-backend:5000` |
| `PISMO`           | не       | почетно писмо: `cirilica` или `latinica`       |

## Зашто један origin

Сесија је колачић, а колачић важи по origin-у. Да иста пријава важи и према Java и према
.NET страни, обе морају да стоје иза истог хоста. Отуда две гране у nginx-у:

- `<префикс>/api/…` → Java
- `<префикс>/net/…` → .NET

Који сегмент модул користи бира се у његовом `api/routes.ts`, при позиву `makeApi`.

## Шта entrypoint мења

1. `<base href>` у `index.html` — из њега webpack изводи путању до bundle-а.
2. `basePath` и `apiUrl` у `config.json` — једино место одакле апликација сазнаје префикс.
3. Локације и upstream-ове у nginx конфигурацији.

Свака измена се и провери; неуспела зауставља подизање. Тихо прескочен `sed` иначе значи
белу страницу коју нико не уме да објасни.
